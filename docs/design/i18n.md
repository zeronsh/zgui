# Localization (i18n)

Status: shipped for 0.1.6: the core (`zgx::i18n`, formatting, size) in
#889, the Luau API, reload, bundle, right to left, types and the lint in
#937. This note says what was built where it differs from the plan (the
types, the binary size defaults).

Locale files typed like themes: `ui.t("key", { args })`, a `ui.locale` that
follows the system, and only the text reading a changed message re-rendering.

## Format: JSON with ICU MessageFormat

`locales/en.json`, `locales/ar.json`, … with nested keys flattened to dotted
names, and messages in ICU MessageFormat syntax:

```json
{ "inbox": { "count": "{n, plural, one {# message} other {# messages}}" } }
```

Supported: `{name}`, `{n, plural, …}` (`#` and `=0`), `{n, selectordinal, …}`,
`{x, select, …}`, `{n, number}`, `{d, date, short|medium|long}`.

Why: it is the same file family as themes (the loader, the watcher and
`bundle` already keep `.json`), it has the widest translator tooling
(Crowdin, Lokalise, FormatJS), and zgx owns a small parser, with plurals and
numbers from ICU4X, the data zgx already uses. Fluent would bring a second
plural and number stack (`intl_pluralrules`) and a file format of its own;
MessageFormat 2 has no stable Rust implementation yet. The parser sits
behind one function, so MF2 can replace it later.

The source locale (`en` unless `source` says otherwise) defines the keys
and their argument names.

## Luau

```lua
ui.i18n { dir = "locales", source = "en" }
ui.text { ui.t("inbox.count", { n = count }) }    -- count: a state
ui.button { label = ui.t("actions.save"), on_click = save }
ui.locale:set("ar")        -- nil follows the system again
print(ui.locale.current)   -- the negotiated locale
```

- `ui.t` returns a Message: a text value, like a template, accepted wherever
  text is (children, `label`, `placeholder`, `title`). Arguments may be
  states or computeds. A plain string would be read once, the untracked-read
  trap the lint already flags.
- `msg:get()` gives the string in handlers, tracked inside computeds.
- `ui.locale` is a `State<string?>`: nil follows the system's preferred
  languages (NSLocale, GetUserPreferredUILanguages, `LANG`), negotiated
  against the locales the app has, with ICU4X's fallback.

## Rust

The catalog and formatting live in zgx core (`zgx::i18n`). The catalog is an
`I18n` handle the app makes and provides to its views, not state on the
`Ui`, so nothing is added to `UiStorage`:

```rust
let i18n = I18n::load(&ui, "locales")?;     // also negotiates the locale
cx.render(provide(i18n.clone(), app()));
text(i18n.t("inbox.count").arg("n", count));
i18n.set_locale(Some("ar"));
```

A script's catalog is the same handle, held by the script's own
environment. `ScriptHost` adds nothing.

## Reactivity

As theme tokens: one lazily made signal per message key. A locale switch or
a file reload sets only the keys whose text changed; a text node subscribes
to its key and its argument states, and nothing else re-renders. Formatting
runs only for the nodes it reaches.

## Right to left

The root's direction follows the negotiated locale
(`Direction::of_language`; the desktop host already sets it from the
system) unless the app set `dir`. Everything `direction` mirrors flips.

## Formatting and binary size

- `icu_plurals` (cardinal and ordinal) and `icu_decimal`, compiled data for
  all locales, behind the feature `i18n`. Measured (dist, on against off at
  one commit): about 90 KB. It is opt-in in zgx-script (`features =
  ["i18n"]`) and on in zgx-run, so `zgx run` has it; Rust-only apps opt in
  through zgx. A host built without it still loads and shows messages, with
  English's plural rules for every locale and numbers as Rust writes them.
- `icu_datetime` behind `i18n-dates`, off by default: measured about
  380 KB more. Without it dates are ISO 8601.

## Types

As built, `zgx types` and `zgx check` write the source locale's keys into
`.zgx/types.d.luau` as a union, `MessageKey`, and `ui.t`'s key is typed
`MessageKey`: an editor completes keys and a misspelled key is a type error.
`zgx.d.luau` has `MessageKey = string` until an app's file replaces it.

- At most 1,000 keys go in the union: luau-lsp rejects a longer one
  ("Exceeded allowed type length" by 2,000 keys). A larger catalog keeps
  `string`, and the `i18n-key` lint still names a key the source lacks.
- Arguments stay loose (a table of numbers, strings, states or functions).
  The planned `Messages` table with `index<Messages, K>` and an overload per
  key both failed in luau-lsp on real catalogs, so argument names are the
  lint's (`i18n-args`), not the types'.

## Lint: `i18n`

- keys missing or extra in a locale, against the source;
- argument names differing from the source's;
- plural categories a locale needs but lacks (Arabic: zero, one, two, few,
  many, other, from ICU4X's rules);
- messages that don't parse;
- `ui.t` with a literal key the source doesn't have.

## Hot reload and bundles

Locale files are watched like theme files; a change reloads the catalog and
keeps state. `bundle` already keeps `.json`, and a bundled host reads them
from the bundle.

## Performance: no hits (acceptance)

The user's rule: no performance hits. It isn't done until each of these is
measured:

1. **Apps that don't use it cost nothing.** The exact gate (arm64
   cachegrind) and CI's x86 perf job show every cell ≤ 0, or a move
   attributed to placement alone. No new fields on hot types (`Node`, rare
   styles, `Opened`, `UiStorage`, `Effects`); no per-frame work; no locale
   query beyond today's direction query. Startup and idle A/B on macOS too.
2. **A translated text costs what a template costs.** A node showing
   `ui.t("inbox.count", { n = count })` costs what the equivalent
   `ui.text { "{n} messages" }` costs, per update and per frame: the
   formatted string is made when the key or an argument changes, never per
   frame. An i18n scene joins the benches (a list of formatted plural
   messages, plus a locale switch) and is compared with its template twin.
   A locale switch touches only the nodes whose text changed.
3. **Binary size within budget.** Plural and decimal data stay on by
   default only within the feature-cost budget (dist, on against off at one
   commit); otherwise they are opt-in, as dates are.
4. **Lazy formatters.** ICU4X's plural rules and decimal formatters are
   made per locale the first time a message needs them, and cached; nothing
   runs at startup until `ui.i18n` (or `I18n::load`) is called.

### What a translated text costs (measured, 0.1.6)

`i18n_bench` shows 200 texts of one count, changed every tick. Exact
instructions per tick, arm64:

| | per tick | over the template |
| --- | ---: | ---: |
| template `"{count} messages"` | 1,748,619 | |
| `ui.t("inbox.count", { n = count })` | 1,769,323 | +1.18% |
| the same, zgx-script's `i18n` (ICU's rules) | 1,786,609 | +2.17% |

Choosing a plural's case was the largest part: it compared category names as
strings. #974 resolves each category's case as the message parses (from
+2.04%). What remains, about 100 instructions a text per update, is what
following a locale costs:

- the tracked read of the key's signal, and its pattern and formatters;
- walking the plural part into its case;
- each argument found by name, through the closure that reads its state.

A template reads its state directly and has none of these.

Tried and measured as nothing:
- `Pattern::format` generic over its closures (0 instructions: LTO already
  inlined its one caller's);
- `text_message` already updates through `text_signal`, as a template does.

Formatting inside the key signal's `with` would save two `Rc` clones, but
a message argument whose function sets the locale would then write the
signal being read (`Signal::set` takes it mutably).

Closing the rest would take compiling each message, per locale, into a
template-like list of segments, swapped as the locale changes. That is a
redesign for about 1%, and it waits until an app's updates are mostly
messages.

## Settled and open

- Settled: `index<Messages, K>` and per-key overloads didn't hold up in
  luau-lsp, so the types are the key union above, capped at 1,000.
- Open: dates take lengths (short, medium, long); skeletons later.
