# Localized text

`zgx::i18n` shows messages from JSON locale files, in the locale negotiated from what the app asks for or the system's preferred languages. Each message is followed: a locale switch or an edited file updates only the texts that changed. In Luau the same catalog is [`ui.i18n` and `ui.t`](reference/text.md#localized-messages).

Plural rules and number formats come with the `i18n` feature, and dates with `i18n-dates`. Both are off by default. Without them a catalog still loads and shows messages, with English's plural rules for every locale.

```toml
[dependencies]
zgx = { version = "0.1", features = ["i18n"] } # or i18n-dates, which includes it
```

## Messages

A locale file is named by its locale (`en.json`, `pt-BR.json`). Nested keys flatten to dotted names, and messages are ICU MessageFormat: `{name}`, `{n, plural, one {# message} other {# messages}}`, `{n, selectordinal, …}`, `{x, select, …}`, `{n, number}`, and with `i18n-dates` `{d, date, short|medium|long|full}` (milliseconds since 1970).

```json
{
  "inbox": { "count": "{n, plural, one {# message} other {# messages}}" },
  "search": "Search"
}
```

## In a view

Make an `I18n`, provide it to the views, and show a message with `text_message`. Its arguments are values or signals; a signal is read each time the message formats, so the text follows it.

```rust,no_run
use zgx::{compose::prelude::*, i18n::I18n, reactive::Signal};

fn inbox(i18n: &I18n, count: Signal<i64>) -> View {
    column().child(text_message(i18n.t("inbox.count").arg("n", count)))
}
```

`I18n::load(&ui, "locales")` reads a directory with `en` as the source, whose file defines the keys; `I18n::load_dir(&runtime, dir, source)` names another source, and `I18n::insert(locale, json)` adds a locale from a string (one compiled in, say). `Message::get` gives the text now, tracked; `Message::arg_with` computes an argument. Provide it with `provide(i18n, view)` and read it with `Context::service`, as any service.

## The locale

`i18n.set_locale(Some("ar"))` asks for a locale and `set_locale(None)` follows the system's preferred languages again. `current()` is the one shown, through its parents (`pt-BR`, then `pt`) to the source, and `direction()` the way it runs. Both are tracked. `refresh_system()` reads the system's languages again when they change.

A key a locale lacks falls back through its parents to the source, then shows the key itself. `on_issue` hears what's wrong once each: a missing key or argument, a message that doesn't parse, a locale with no file.

## Options that follow it

A select's options can follow a signal with `zgx_components::select_live`, relabelled in place in a new locale and added and removed by their value. The other components name their parts in the current locale.
