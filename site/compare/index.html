How it was measured

Same work

Each framework runs the same UI from a shared workload crate: a streaming transcript and a 100,000-row virtual list (lab), a 1280×800 dashboard where most values change every tick (heavy), and dots and text animated at the display's rate (animation). Lab and heavy updates arrive 60 times a second, and a run counts only if it delivers 58–61 a second; the animation draws as often as each framework presents.

Sampling

Every trial runs 20 seconds; the first 5 are excluded and the next 15 sampled every 50 ms. Three repeats per framework and mode, in rotated order, with the desktop alone measured each repeat. Frame pacing is timed separately by capturing each window's frames, eight 8-second captures per framework and mode: where an app's 60 Hz timer falls against the display's refresh is fixed for a capture and varies between them, moving one capture's 99th percentile by 5 ms or more. The share of intervals past 25 ms (late frames) moves much less.

GPU, fairly

GPU work is how long the GPU ran each app's vertex and fragment work, from Metal System Trace captures of each app alone (5 seconds, three per framework and mode). IOKit's per-app GPU time, also shown, adds each command buffer's fixed cost and stretches as the GPU clocks down; it is multiplied by the mean active clock to give megacycles a second.

Memory

Physical footprint, as Activity Monitor reports it, including GPU memory the process owns. Any process that has used the GPU in the last second or two holds about 180–190 MB of Metal driver memory, so differences come down to the last 50–60 MB.

Not isolated

A personal Mac in use: a live wallpaper and other apps kept the GPU about 45% busy, and per-app GPU readings vary two- to threefold between runs. Small GPU differences are within that noise; CPU and the share of late frames are steadier.
