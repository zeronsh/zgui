How this was measured

  • Machine: Apple M5 Max (Mac17,6, 18 cores, 128 GB), macOS 26.4 (25E246), AC Power.
  • Displays: 2 × Studio Display XDR (3200 x 1800 @ 120.00Hz); the window on the main display, nothing covering it.
  • Builds: zgx and GPUI Fast with their dist profile (release, fat LTO, one codegen unit), rustc 1.96.0 (ac68faa20 2026-05-25); MyGo v0.6.3 (1524290, MIT) built with go1.27.3 darwin/arm64, go build -trimpath -ldflags=-s -w, cgo off. Every framework uses the system allocator. zgx at c742a39.
  • Trials: each a fresh launch, the first 5 s discarded and the next 10 s sampled every 50 ms; 3 trials of each mode, in alternating order, and 2 more of any whose CPU or GPU spread past 10% of its median; idle 3 times in the dashboard, 20–30 s after launch. Every trial had to run as long as asked, at 60 updates a second. Medians are shown, the trials' range beside them. Frame timing is 2 separate 8 s captures of each mode.
  • CPU: the app process's CPU time over the sample, as a percentage of one core (it can exceed 100).
  • WindowServer CPU: the CPU of macOS's compositor, which puts every app's frames on screen, over the same sample: what showing the app costs the system beside the app's own CPU. It includes what WindowServer does anyway (the desktop alone, measured each repeat, is beside each chart's title).
  • GPU power: the whole GPU's energy over the sample, from the system's energy model (IOReport), in milliwatts, less the desktop alone (measured each repeat; beside each chart's title). It counts everything the GPU does for the app, the window server's compositing of its window included, so a framework is charged for how it presents its frames as well as for drawing them.
  • App GPU time (secondary): the GPU time macOS accounts to the app's process, as cycles at the GPU's mean clock. It includes the time from each submission to the GPU starting it, about half a millisecond after the GPU idles, so an app that draws small frames often reads high: measured with Metal System Trace, zgx's animation frames execute in 46 µs against GPUI Fast's 318 µs, yet this counter charges zgx more. It also moves with whatever else keeps the GPU awake. Kept for comparison with earlier runs.
  • Frame time: the 99th percentile of the intervals between frames shown on screen; at 60 updates a second, 16.7 ms is on time (8.3 ms for the animation, drawn at 120 Hz). Long frames are intervals over 25 ms.
  • Unfilled rows (the list): the window captured 10 times a second for 8 s per mode; a capture counts when a stretch of the rows' padding over 24 points shows the window's background, where no row was drawn.
  • Memory: the process's physical footprint (what Activity Monitor shows: resident memory plus GPU memory it owns), averaged over the sample.
  • The list widgets: zgx's measured virtual list, the same list from a Luau script (ui.list {{ measured = true }}), and GPUI Fast's list measure each row as they lay it out; MyGo's ui.List keeps its place by an anchor row and estimates unmeasured rows at the average height.

Caveats

  • Compare within this run only: the same binaries measured hours apart read differently (the machine's state changes), so a cell is not comparable across runs, while the frameworks in one run share its session.
  • Idle memory is two-level: an idle window settles at one of two levels about 25 MB apart, launch to launch, as the Metal driver returns its startup memory. Which level a launch lands on is the driver's timing, not the app's, so read idle memory with its range.
  • MyGo is immediate mode: each frame it draws builds and draws its whole window, which is how MyGo apps work.
  • WindowServer spends more CPU on zgx’s window than on a rival’s in 9 of 10 tests (its chart follows CPU in each scene): showing zgx’s frames costs the system more than the others’, a cost zgx has yet to bring down.
  • GPU power is within the trials’ spread, or higher for zgx, in: animation (animating) against GPUI Fast, animation (animating) against MyGo.
  • Until 2026-10-25 these pages' GPU figure was app GPU time; it is now GPU power, which measures what the GPU spends rather than how long it was held (see How this was measured). In the animation, zgx uses 31% more than GPUI Fast, 3% less than MyGo on app GPU time and 9% less than GPUI Fast, 7% more than MyGo on power.
  • Binary size is not compared.
  • One machine, one session; a personal Mac in use, other applications kept running (the run waited until the machine was quiet). Windows and Linux are not compared here.
